# PVDBASEBALL — developer guide

React + TypeScript fantasy baseball draft tool: roto big board, consensus rankings, matchup analyzer, live odds, news feed, and hitter spray charts. Client-only; data ships as generated TypeScript modules.

## Stack

- **Vite 5** + **React 18** + **TypeScript**
- **Tailwind CSS** for styling
- **`@tanstack/react-virtual`** for long draft/consensus tables
- Path alias: `@/` → `src/`

## Quick start

```bash
npm install
cp .env.example .env   # optional: odds API key
npm run dev
```

- **Dev:** `npm run dev` → Vite on `http://localhost:5173` (or next free port)
- **Production build:** `npm run build` → output in `dist/`
- **Preview build:** `npm run preview`

## Environment variables

Only names prefixed with `VITE_` are exposed to the browser (see `src/config/env.ts`).

| Variable | Required | Purpose |
|----------|----------|---------|
| `VITE_ODDS_API_KEY` | No | [The Odds API](https://the-odds-api.com/) key for MLB lines. If unset, the app uses mock odds. |

Build-time (not bundled):

- `GITHUB_PAGES=true` — sets Vite `base` to `/PVDBASEBALL/` for GitHub Pages (see `vite.config.ts`).

## Data pipeline

1. **`rawRoster.ts`** — roster identity only (`name`, `pos`, `team`, `adp`, `posRank`). Regenerated by Python/Node scripts in `scripts/` (see `generate_fantasy_pool.py` / `generate-fantasy-pool.mjs`).
2. **`playerStats.ts`** / **`statLineBuilder.ts`** — projected stat lines keyed by name.
3. **`playerWriteups.ts`** — blurbs keyed by name.
4. **`players.ts`** — merges the above through `buildPlayer.ts` into `Player[]`. **Do not** hand-edit `rawRoster.ts` for large changes; regenerate and commit.

**Consensus board:** `consensusRankings.ts` is generated (e.g. `scripts/generate_consensus.py`); types in `types/consensus.ts`.

## External APIs (browser)

- **Odds:** `services/oddsApi.ts` — CORS may block in some environments; mock fallback exists.
- **News:** `services/newsService.ts` — MLB Stats API (transactions/injuries when available) + RSS feeds via `api.rss2json.com` (rate limits apply).
- **Matchup slate:** `data/todaysGames.ts` — static slate; `fetchTodaysGames()` is the hook for future MLB Stats API wiring.

## Conventions worth knowing

- **Player identity:** `findPlayerIdByName` / `normalizePlayerName` in `utils/playerLookup.ts` for cross-feature name matching (news, odds row actions).
- **Pitcher vs hitter:** `getPlayerType` / `primaryPosFromPos` drive which stats and UI (e.g. spray chart only for hitters / two-way hitting side).
- **Filters:** `useFilteredPlayers.ts` centralizes draft + consensus filters; `FilterBar` is shared.

## Scripts (maintenance)

| Script | Purpose |
|--------|---------|
| `python3 scripts/generate_fantasy_pool.py` | Regenerate `src/data/rawRoster.ts` (and related outputs if script writes them) |
| `node scripts/generate-fantasy-pool.mjs` | Alternative generator; keep output shape aligned with `RawPlayer` |

After regenerating data, run `npm run build` to confirm TypeScript passes.
